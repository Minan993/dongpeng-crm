# 上线就绪评估（第 6 步检查）

## 结论

当前仓库**不具备生产上线条件**，仅达到“可运行 MVP 骨架”阶段（适合内网联调/演示，不建议直接公网生产）。

## 已具备（可加分项）

1. 基础容器编排与环境变量示例：`docker-compose.yml`、`.env.example`。
2. FastAPI 后端具备基础健康检查、JWT 登录、RBAC 权限校验骨架。
3. 核心业务模型与部分 API 路由已经建立（线索/客户/量尺/报价/订单/售后/回访）。
4. PostgreSQL 初始化 SQL、初始化脚本、备份恢复脚本已提供。

## 阻断上线（必须先补齐）

1. **自动化测试不可执行**：当前测试依赖未安装会直接报错（`sqlalchemy`、`jose`），无法形成上线前验证闭环。
2. **前端仍为占位壳**：仅有工作台/线索/客户静态页面提示，未完成完整业务页面与真实联调。
3. **部署链路未完成生产校验**：当前环境缺少 `docker` 命令，无法验证 `docker compose up` 的真实启动结果。
4. **数据库迁移策略偏“基线 SQL”**：尚未形成 Alembic 版本化迁移与回滚流程。
5. **安全基线不足**：默认 `CORS=*`、`SECRET_KEY` 示例弱口令，且未给出 HTTPS/TLS 与生产反向代理全流程校验记录。
6. **测试覆盖偏低**：现有测试多为最小样例，关键业务流程（线索→订单→售后）与权限边界未形成可回归用例集。

## 上线前最小整改清单（Go-Live Checklist）

1. 安装依赖并跑通 `pytest`、后端启动、自检脚本。
2. 完成前端真实页面（列表/筛选/分页/表单/权限按钮）并与后端联调。
3. 将部署切到 Nginx 反代入口（80/443），并输出可复现的启动与回滚手册。
4. 补齐 Alembic 迁移（至少：初始版本 + 一次增量 + 回滚验证）。
5. 强化安全配置：生产环境 CORS 白名单、强 `SECRET_KEY`、管理员首登改密流程验证、上传限制验证。
6. 增加接口集成测试（认证、RBAC、导入导出、订单欠款、售后流转）。

## 建议的上线分级

- **当前**：内网联调 / 方案演示（可）。
- **补齐清单后**：预发环境灰度（可）。
- **完成压测与运维监控后**：生产上线（可）。
